# 项目目标与进度

本项目面向 AI6127 Deep Neural Networks for Natural Language Processing（2026）课程作业，任务是基于 arXiv 标题和摘要的检索增强论文推荐。使用入口见 [README](../README.md)，数据证据见[数据与构建](data.md)，评估设计见[实验与评估](evaluation.md)。

## 依据与状态口径

需求依据为用户提供的 `Assignment.pdf`（4 页，课程要求）与 `arxiv_paper_recommendation_proposal_zh.pdf`（1 页，方案草案）；两份原文件未存放在仓库中。下文将材料中的要求与计划作为项目背景，推荐接口已于 2026-10-31 更新，其余源码状态核对于 2026-10-28，语料与查询示例已于 2026-10-19 同步更新，不计未纳入 Git 的本地实验材料。列出剩余事项不表示已执行开发、标注、评估或提交。

“已实现”表示存在对应代码；“已有材料”表示可读取现有文件；二者均不代表已经完成质量评估。本次文档核对未运行检索、模型推理或测试。

## 目标与当前输出

目标流程为：研究需求 → 检索论文 → 将候选标题和摘要提供给生成模型 → 输出 Top-10 推荐、简短理由及对应来源。理由应能由所引用摘要支持；摘要无法支撑的结论不能作为已证实的推荐依据。

`SearchEngine` 生成英文关键词、语义查询和整合评分查询，返回 `list[SearchResult]`。结果含内部 ID、论文 ID、标题、摘要和方法分数。调用方可将研究请求与检索结果交给 `RecommendationGenerator` 或 `EvidenceGroundedRecommendationGenerator`，两者实现共同的 `BaseRecommendationGenerator` 接口，统一返回关联原始检索结果的 `list[PaperRecommendation]`。理由包含 1～2 处 `[[cite]]原文片段[[/cite]]`，两种实现都校验原文精确匹配；证据增强版进一步通过提示词约束具体主张由引用片段支持，但程序不自动证明语义支持性。完整引用模块与网页展示仍待实现。

Top-10 是提案中的产品目标；检索 API 默认返回上限为 20，可通过 `limit` 调整候选数量。推荐生成先取前 30 个候选并去重，最多 5 个并发请求逐篇判断，再仅对初筛推荐项集中筛选排序，两阶段均开启 thinking。最终数量为 `min(limit, 初筛推荐数)`，默认 `limit=10`，初筛全部不推荐时直接返回空列表。检索列表及其数量不等同于已生成的推荐。

| 要求／问题 | 当前证据 | 尚需完成 |
| --- | --- | --- |

| Q2：简单友好的 Web／移动查询 UI；5 个查询、结果和查询速度 | 已有 Python API；仓库未提供五查询结果与耗时记录 | 实现界面、来源展示；保存至少五查询的结果与耗时，Python API 尚不能替代要求的 UI |

## 提案与实际实现的差异

| 提案中的计划 | 当前实际情况 |
| --- | --- |
| 拟使用 Kaggle arXiv／arXiv Paper Abstracts | 现有快照来自 `data-preprocessing` 分支迁移，全部 10,000 条记录的 `source` 字段为 `arxiv_api`；当前分支没有采集源码，不能据此还原完整采集过程 |
| 至少 10,000 篇论文，以标题＋摘要作为 passage | 当前为 10,000 篇，一篇一个段落；实际 `text` 为标题、两个换行和完整摘要 |
| sparse、dense、hybrid，外加一项待定 retrieval innovation | 当前已有普通及标题加权 BM25、单查询及多查询 HNSW、三种混合策略、查询生成与重排；创新如何分组及其收益尚未通过实验确定 |
| 网页显示论文与来源，输出 Top-10 及理由、引用 | 已有两阶段生成和最多 10 条推荐，两种方法的理由均内嵌带标记的标题／摘要原文；Web 和完整引用包仍为占位，`SearchResult` 不包含作者、URL 或推荐理由，生成结果由推荐记录承载 |
| 约 100 条研究需求、至少 1,000 个 query–paper 相关性标注，至少两位标注者 | 仓库未提供人工评估集与一致率记录 |
| 比较基线与检索／下游创新 | 已提供生成固定候选与配对运行框架，可记录状态、输出与耗时；尚无正式相关性、生成质量、消融或性能结果 |

## 剩余工作与交付依赖

1. 知识库规模已达标，统计、向量、数据库和索引已同步；仍需记录实际来源、采集条件、清洗与分块规则。现有归档的语料哈希与当前 JSONL 文件哈希不同，需确认数据与向量的来源对应关系，见[归档模型元数据](data.md#归档模型元数据)。
2. 为现有推荐生成补充作者、日期、URL 等完整引用元数据，并在 `web/` 提供简单查询与结果展示。下游创新已实现[原文证据生成](evidence_grounded_generation.md)，两种生成器均复用 `LLM_MODEL` 配置；Web 框架及正式实验的检索、查询指令与生成模型配置尚待确定。
3. 按提案准备去重研究需求、候选池和人工标注；先划分开发用途与留出评估用途，再进行调参与正式比较。
4. 保存五查询的耗时与结果，在共同标签和明确基线下开展检索比较；对生成输出进行证据支持性和需求相关性评估，并记录延迟、吞吐和成本。
5. 整理创新前后实例、必要消融、系统限制及报告，归档知识库、查询结果、标注集、生成答案和源码运行环境。
