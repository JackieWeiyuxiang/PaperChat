# 项目目标与进度

本项目面向 AI6127 Deep Neural Networks for Natural Language Processing（2026）课程作业，任务是基于 arXiv 标题和摘要的检索增强论文推荐。使用入口见 [README](../README.md)，数据证据见[数据与构建](data.md)，评估设计见[实验与评估](evaluation.md)。

## 依据与状态口径

需求依据为用户提供的 `Assignment.pdf`（4 页，课程要求）与 `arxiv_paper_recommendation_proposal_zh.pdf`（1 页，方案草案）；两份原文件未存放在仓库中。下文将材料中的要求与计划作为项目背景，源码状态核对于 2026-10-16，语料与查询示例已于 2026-10-19 同步更新，不计未纳入 Git 的本地实验材料。列出剩余事项不表示已执行开发、标注、评估或提交。

“已实现”表示存在对应代码；“已有材料”表示可读取现有文件；二者均不代表已经完成质量评估。本次文档核对未运行检索、模型推理或测试。

## 目标与当前输出

目标流程为：研究需求 → 检索论文 → 将候选标题和摘要提供给生成模型 → 输出 Top-10 推荐、简短理由及对应来源。理由应能由所引用摘要支持；摘要无法支撑的结论不能作为已证实的推荐依据。

当前 API 已实现基础检索和生成：`SearchEngine` 返回 `list[SearchResult]`，`RecommendationGenerator` 可基于候选论文标题和摘要生成最多 10 条理由，并保留每条结果对应的 `SearchResult`。尚未实现理由的自动支持性核验、作者／来源 URL 元数据读取及 Web 展示，因此目前还不是完整产品流程。

检索基线的主要已知问题是：BM25 依赖词项重合且标题、摘要等权；HNSW 对精确术语和硬约束可能不如词面匹配直接；混合方法尚未在人工标签上比较。已实现一项独立 retrieval innovation：Title-Boosted BM25 将 FTS5 的标题与摘要权重设为 3:1，作为对等权 BM25 的字段感知排序对照。该权重是初始假设，效果尚未验证。P3 的基础 generation 也已实现：根据检索结果生成最多 10 条理由并保留论文 ID。评估程序、标注需求和生成边界见[实验与评估](evaluation.md)及[检索 API](retrieval.md#检索创新title-boosted-bm25)。

Top-10 是提案中的产品目标；当前 API 默认返回上限为 20，可通过 `limit=10` 获取最多 10 篇候选。检索列表及其数量不等同于已生成的推荐。

## 提案与实际实现的差异

| 提案中的计划 | 当前实际情况 |
| --- | --- |
| 拟使用 Kaggle arXiv／arXiv Paper Abstracts | 现有快照来自 `data-preprocessing` 分支迁移，全部 10,000 条记录的 `source` 字段为 `arxiv_api`；当前分支没有采集源码，不能据此还原完整采集过程 |
| 至少 10,000 篇论文，以标题＋摘要作为 passage | 当前为 10,000 篇，一篇一个段落；实际 `text` 为标题、两个换行和完整摘要 |
| sparse、dense、hybrid，外加一项待定 retrieval innovation | 已有两种基础方法、三种混合策略及标题加权 BM25 创新；创新收益尚未通过实验确定 |
| 网页显示论文与来源，输出 Top-10 及理由、引用 | 已有基础推荐理由生成器；Web 与引用模块仍为占位，`SearchResult` 不包含作者或 URL |
| 约 100 条研究需求、至少 1,000 个 query–paper 相关性标注，至少两位标注者 | 仓库未提供人工评估集与一致率记录 |
| 比较基线与检索／下游创新 | 仓库未提供相关性指标、生成评估、消融或耗时记录 |

## 剩余工作与交付依赖

1. 知识库规模已达标，统计、向量、数据库和索引已同步；仍需记录实际来源、采集条件、清洗与分块规则。现有归档的语料哈希与当前 JSONL 文件哈希不同，需确认数据与向量的来源对应关系，见[归档模型元数据](data.md#归档模型元数据)。
2. P3 已在 `recommendation/generation/` 实现基础证据驱动理由生成；后续需补齐来源 URL、引用对应及 P4 的下游创新和评估，并由 P1 在 `web/` 提供查询与结果展示。
3. 按提案准备去重研究需求、候选池和人工标注；先划分开发用途与留出评估用途，再进行调参与正式比较。
4. 保存五查询的耗时与结果，在共同标签和明确基线下开展检索比较；对生成输出进行证据支持性和需求相关性评估，并记录延迟、吞吐和成本。
5. 整理创新前后实例、必要消融、系统限制及报告，归档知识库、查询结果、标注集、生成答案和源码运行环境。
