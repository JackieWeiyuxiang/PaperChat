# 项目目标与进度

本项目面向 AI6127 Deep Neural Networks for Natural Language Processing（2026）课程作业，任务是基于 arXiv 标题和摘要的检索增强论文推荐。使用入口见 [README](../README.md)，数据证据见[数据与构建](data.md)，评估设计见[实验与评估](evaluation.md)。

## 依据与状态口径

需求依据为用户提供的 `Assignment.pdf`（4 页，课程要求）与 `arxiv_paper_recommendation_proposal_zh.pdf`（1 页，方案草案）；两份原文件未存放在仓库中。下文将材料中的要求与计划作为项目背景，完成情况以 2026-10-16 工作区的源码与仓库数据为准，不计未纳入 Git 的本地实验材料。列出剩余事项不表示已执行开发、标注、评估或提交。

“已实现”表示存在对应代码；“已有材料”表示可读取现有文件；二者均不代表已经完成质量评估。本次文档核对未运行检索、模型推理或测试。

## 目标与当前输出

目标流程为：研究需求 → 检索论文 → 将候选标题和摘要提供给生成模型 → 输出 Top-10 推荐、简短理由及对应来源。理由应能由所引用摘要支持；摘要无法支撑的结论不能作为已证实的推荐依据。

当前流程止于检索：`SearchEngine` 生成英文关键词、语义查询和整合评分查询，返回 `list[SearchResult]`。结果含内部 ID、论文 ID、标题、摘要和方法分数。LLM 目前仅生成检索输入；它没有阅读检索结果并生成推荐理由。因此，当前实现尚未形成完整的 retriever–generator 闭环。

Top-10 是提案中的产品目标；当前 API 默认返回上限为 20，可通过 `limit=10` 获取最多 10 篇候选。检索列表及其数量不等同于已生成的推荐。

| 要求／问题 | 当前证据 | 尚需完成 |
| --- | --- | --- |
| Q1：知识库至少 10,000 篇文档／段落、100,000 词；说明来源、清洗、分块和存储，报告文档数、段落数、词数、不同词数 | 6,000 篇／段落、1,145,234 词，词数已超过门槛；已有 JSONL、向量、数据库和索引 | 至少补足 4,000 篇／段落；补齐可复现采集清洗流程、来源及筛选记录 |

| Q2：简单友好的 Web／移动查询 UI；5 个查询、结果和查询速度 | 已有 Python API；仓库未提供五查询结果与耗时记录 | 实现界面、来源展示；保存至少五查询的结果与耗时，Python API 尚不能替代要求的 UI |

| 最终交付：报告、数据包、源码包与运行说明 | 已有源码、运行文档与知识库快照 | 补齐查询与检索结果、评估集、生成结果、实验分析、报告与展示材料；形成可分享的数据包和源码包 |

## 提案与实际实现的差异

| 提案中的计划 | 当前实际情况 |
| --- | --- |
| 拟使用 Kaggle arXiv／arXiv Paper Abstracts | 现有快照来自 `data-preprocess` 分支迁移，全部 6,000 条记录的 `source` 字段为 `arxiv_api`；当前分支没有采集源码，不能据此还原完整采集过程 |
| 至少 10,000 篇论文，以标题＋摘要作为 passage | 当前为 6,000 篇，一篇一个段落；实际 `text` 为标题、两个换行和完整摘要 |
| sparse、dense、hybrid，外加一项待定 retrieval innovation | 当前已有两种基础方法、三种混合策略、查询生成与重排；创新如何分组及其收益尚未通过实验确定 |
| 网页显示论文与来源，输出 Top-10 及理由、引用 | 当前只返回检索结果，Web、推荐生成和引用包仍为占位；`SearchResult` 不包含作者、URL 或推荐理由 |
| 约 100 条研究需求、至少 1,000 个 query–paper 相关性标注，至少两位标注者 | 仓库未提供人工评估集与一致率记录 |
| 比较基线与检索／下游创新 | 仓库未提供相关性指标、生成评估、消融或耗时记录 |

## 剩余工作与交付依赖

1. 补足知识库规模并记录实际来源、采集条件、清洗与分块规则；更新统计、向量和索引。现有归档的语料哈希与当前 JSONL 文件哈希不同，需同时确认数据与向量的来源对应关系，见[归档模型元数据](data.md#归档模型元数据)。
2. 在 `recommendation/` 实现读取检索证据的生成、论文引用和下游创新；在 `web/` 提供简单查询与结果展示。具体框架、生成模型与创新方案尚未确定。
3. 按提案准备去重研究需求、候选池和人工标注；先划分开发用途与留出评估用途，再进行调参与正式比较。
4. 保存五查询的耗时与结果，在共同标签和明确基线下开展检索比较；对生成输出进行证据支持性和需求相关性评估，并记录延迟、吞吐和成本。
5. 整理创新前后实例、必要消融、系统限制及报告，归档知识库、查询结果、标注集、生成答案和源码运行环境。
